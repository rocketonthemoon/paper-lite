1. LABELLED UNDO HISTORY  ("History" tab in the right panel)
------------------------------------------------------------
Today: undoStack holds bare snapshots (server.js commit()). `source` is passed
to commit() but dropped, so nothing can show who did what.
- [ ] Store entries as { snapshot, source, tool, label, nodeIds, layerCount, at }.
      source = "you" | "mcp" (MCP writes come through mcp-tools.js; browser writes
      come through who(req) / x-client-id).
- [ ] Derive a label per mutation: MCP tool name + target layer name,
      e.g. "write_html · Inspector", "set_text_content · 3 layers".
- [ ] GET /api/history  ->  { entries, cursor, limit: 60 } and an SSE "history" event.
- [ ] UI: Design | History | Notes tabs in #right. Rows show an AI/You chip, label,
      time and layer count. The current step is highlighted; redo-able steps are dimmed.
- [ ] Click a row = jump to that step (repeat undo/redo to that cursor).
- [ ] "Undo last agent run": undo back past the most recent consecutive run of
      source="mcp" entries.
- [ ] Filter button: All / Agent / You.

2. CHECKPOINTS  (named restore points)
---------------------------------------
- [ ] "Save checkpoint" button: store a full project snapshot with a name in
      DATA_DIR/projects/<id>.checkpoints.json. Unlike undo, these persist across
      restarts and aren't capped at 60.
- [ ] Auto checkpoints: on project creation, and before the first MCP write after
      2+ minutes of no MCP writes (an "agent run" start).
- [ ] Restore = one undoable mutation that replaces pages/nodes with the checkpoint.
- [ ] Show a checkpoint divider inside the History timeline.
- [ ] MCP tools: save_checkpoint(name), list_checkpoints(), restore_checkpoint(id),
      so an agent can make its own safety net before a big rewrite.

3. COMMENTS  (pinned to layers; how you talk to your agents)
------------------------------------------------------------
Designs: "Editor · Comments (new)" and "04 · Agents & Comments".
- [ ] Data: project.comments = [{ id, nodeId, status: open|read|replied|resolved,
      agentsCanSee: true, messages: [{ id, author: "you" | <agent name>,
      text, at, linkedStep? }], readAt?, createdAt }].
      Anchored to nodeId (not x/y) so pins follow the layer; if the layer is
      deleted, keep the thread and show "Layer deleted" with Restore (undo).
- [ ] Comment tool "C" in the toolbar (after Text) + "Comment" in the context bar.
      Placing state: hover outline on the target layer, plus-pin and the hint
      "Comment on <layer>". Click opens a new thread with the composer focused.
- [ ] Pin (26px, teardrop, numbered) at the layer's top-left. States: open (ink),
      read by agent (ink + dashed orange ring), agent replied (orange),
      resolved (grey check, hidden unless "Show resolved pins on canvas").
- [ ] Thread popover (360px, float shadow): layer name, Resolve, ⋯ menu;
      messages with You / agent avatar + MCP badge; agent replies can carry a
      linked change (history step) with View (jump) and Undo.
      Composer: Ctrl+Enter to send, "Agents can see this" toggle.
- [ ] Right panel tab "Comments (n)": Open / Resolved segments; rows show pin,
      layer, status ("Claude replied", "Read 10:11", "Waiting · 2m"), preview,
      message count and linked changes. Click = zoom to layer + open thread.
- [ ] Layer tree: comment count indicator on rows (orange when an agent replied).
- [ ] Toast when an agent replies: "Claude replied to your comment" + View.
- [ ] MCP tools:
        get_comments({ status?, nodeId? })  -> marks read, sets readAt
        reply_to_comment({ id, text, linkStep?: true }) -> status "replied";
            linkStep attaches the most recent history entry from this session
        resolve_comment({ id })
      get_basic_info includes "openComments: n" so agents notice them.
- [ ] Comments are excluded from HTML/JSX/ZIP export.

4b. AGENT CURSOR  (live pointer for each connected agent)
--------------------------------------------------------
Shown in "Editor" and "Editor · History & Notes (new)": an orange pointer with a
name tag ("Claude") and the tool it's running ("update_styles · padding").
Agents have no real mouse, so the cursor follows the layers they touch.
- [ ] Extend the presence SSE payload: { agents: [{ id, name, color, nodeIds,
      tool, detail, at }] }. Fill it from the MCP handler (tool name + main
      argument, e.g. the style keys for update_styles, the layer name for write_html).
- [ ] Agent identity: use the MCP client name from initialize (clientInfo.name)
      as the label. Give each session a stable colour (Claude orange #d97757
      first, then the pastel set) so two agents get two cursors.
- [ ] Position: the bottom-right corner of the bounding box of nodeIds, converted
      to stage coordinates in updateOverlay(). Animate between targets with a
      ~250 ms ease so you can see where the agent moved.
- [ ] Read-only tools (get_screenshot, get_computed_styles, get_jsx) move the
      cursor too, with a lighter "looking" state (outline pointer, no fill).
- [ ] Fade the cursor out 8 s after the agent's last call; remove it when
      finish_working_on_nodes is called.
- [ ] Clicking the cursor tag selects the agent's current nodes (zoom-to-selection).
- [ ] Replaces the old "Agent · <tool>" pill on the agent box.
